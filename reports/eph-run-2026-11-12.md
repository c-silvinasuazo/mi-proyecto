## Failures that are not eph setup

- **REG-105 (session freeze):** a page opened before the freeze can still take the frozen session off the attendee's My Schedule. It failed every time the test reached that step: 6 runs, including 3 in a row on Nov 12. This looks like a product bug; it still has to be confirmed on production before it's filed.
- **ENG-87:** a session type with a comma is split into two types. Open data bug, expected to fail until it's fixed.
- **ENG-2217 (Speaker Tools):** now recorded, and it confirms the request: the two option names are swapped. With only "Edit session description" on, the speaker gets "Edit Session" (title, video stream, button link, photo); with only "Edit session details" on, they get "Edit Description" (the description editor). Expected to fail until the names are switched. Side finding on eph: the speaker account had no name, and one nameless person breaks Attach People in the session form for every session; the test gives the speaker a name first.
- **ENG-241:** skipped on purpose. The bug is characters drawn as boxes in the badge preview, which needs a visual check.

## Changes since Nov 10

- **REG-113 (QR export, ENG-544/545/546) got further.** On Nov 10 it stopped at "Self Check-in did not save". On Nov 12 Self Check-in saves, and the export shows only the selected sessions, 3 per page on 2 pages. It now fails only at "Export all (PDF)", which stays at "Processing. You'll receive an email when it's ready." (eph issue #2).
- **REG-105's unfreeze failure was a test issue, now fixed.** In the full run, unfreezing seemed not to save. The test waited for any POST to /editor/schedule, and the editor also sends those to load data, so it sometimes reopened the session before the save landed. It now waits for the save itself; in 3 runs in a row the unfreeze step passed every time.
